# Suites whose runs need a live worker (PIDASHCONV-821, PIDASHCONV-983).
#
# The matrix boots no worker by default: consumed .delay() side effects break
# HTTP suites that do not expect them (see the app-project workflow). The
# suites listed here are the exception: they assert on rows created only
# inside a task, so without a consumer their runs fail. The workflow starts
# `celery -A pi_dash worker` (solo, redis broker) for these suites before
# the Django run and stops it at the reset; the Rust run gets
# `pidash-api worker` (solo, Postgres queue) instead — Rust handlers
# enqueue-only like Django, and a Django worker on redis would never see
# the Postgres queue (nor would it see AMQP publishes).
#
#   app_intake: intake-issue CREATE publishes issue_description_version_task;
#     the versions tests poll until the rows exist (proven locally: 45/45
#     with a worker each side, versions tests time out without one).
