# Feature inventory — Project settings (Phase 3)

Area prefix: `PSET-`. Editions covered: oss, cloud, desktop.
Sources surveyed: routes `apps/web/app/(all)/[workspaceSlug]/(settings)/settings/projects/`
(list, per-project general, members, states, labels, five feature tabs, estimates,
github, automations, schedulers), component folders
`apps/web/core/components/project/` (details form, member list, publish, create,
archive, join/leave, scheduler bindings, settings helpers),
`apps/web/core/components/project-states/` (state groups and rows),
`apps/web/core/components/labels/` (label hierarchy and drag-and-drop),
`apps/web/core/components/settings/` (settings shell, project sidebar, headers),
the cloud/community variants under `apps/web/ce/components/projects/settings/`,
the project/member/state/label/estimate/github service layer, and the API layer
(project, member, state, label, estimate URL maps plus the project/member/state
views and serializers they point at). Sweeps for edition or shell differences
(desktop overlay, cloud overlay, command palette entries, keyboard shortcuts,
realtime channels) found no project-settings-specific code. Behavior below is
paraphrased from those sources; no UI copy, code, class names or message text
is reproduced.

Row format follows the Parity page: ID, capability, who, edition, old entry
point, API, acceptance, parity test (empty until the oracle run), status.
