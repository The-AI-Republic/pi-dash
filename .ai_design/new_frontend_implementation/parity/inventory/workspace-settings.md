# Feature inventory — Workspace settings (members, integrations, webhooks, API tokens, billing, exports entry) (Phase 3)

- Area: Workspace settings — general details, members and invitations, third-party
  integrations, webhooks, personal access tokens, billing and plans, and the exports
  settings entry point
- ID prefix: `WSET-`
- Editions: oss, cloud (billing, plans, license upsell), desktop
- Status of this file: draft for human sign-off (H-signoff-3 via NEWFRONT-10)
- Method: read of the old sources listed in the coverage checklist (routes
  `settings/(workspace)/**`; `core/components/{workspace,integration,web-hooks,api-token,license,instance}`;
  `ce/components/{workspace,license,instance}`; plus the backing services, stores and
  permission constants). The old app was not run against a seeded stack in this pass
  (no local backend here); every row must still pass the oracle run (NEWFRONT-64)
  against the live old app before implementation starts. The cloud `ee-overlay` tree
  is not in this checkout, so cloud-only behavior is derived from the `ce/` seams and
  marked as needing oracle confirmation. Descriptions are paraphrased; no old strings,
  code, or styles are reused.
- Overlaps recorded, not rowed twice: the personal-access-token screens live under the
  profile settings routes (owned by NEWFRONT-65); the token capability rows below pin
  the behavior and name the profile entry point so the two areas can dedupe at
  sign-off. The export form and export history themselves are owned by NEWFRONT-59;
  only the settings entry point is rowed here.
- Negative rows: WSET-031 (no paid-plan upgrade modal; target per main#572).
