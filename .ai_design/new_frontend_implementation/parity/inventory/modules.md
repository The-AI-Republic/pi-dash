# Feature inventory — Modules (Phase 3)

- Area: Modules — project modules list (list, board, timeline layouts), module detail with
  work items and analytics sidebar, archived modules, module links, filters and ordering
- ID prefix: `MOD-`
- Editions: oss, cloud, desktop
- Status of this file: draft for human sign-off (H-signoff-3 via NEWFRONT-10)
- Method: read of the old sources listed in the coverage checklist (routes, `core/components/modules`,
  the module and module-filter stores, module services, filter/sort helpers, command-palette wiring
  and constants). The old app was not run against a seeded stack in this pass (no local backend here);
  every row must still pass the oracle run (NEWFRONT-50) against the live old app before implementation
  starts. No module-specific code was found in the `ce/` tree, the private cloud overlay seams, or
  `desktop-overlay/`, so every row is edition `all` and the desktop/edition rows are recorded as
  negative rows. The running-app pass may add rows here as comments. Descriptions are paraphrased;
  no old strings, code, or styles are reused.
- Dropped by decision, not rowed: product-analytics element ids on the header and card buttons (no
  third-party analytics in the new app). Negative rows (MOD-039 through MOD-043) record load-bearing
  absences the new app must preserve.
