# Feature inventory — Issues (Phase 1)

Area: **Issues** — layouts (list, board/kanban, spreadsheet, calendar, gantt); detail; peek; filters & display options; bulk edit; sub-issues; relations; links; attachments; reactions; subscriptions; comments/activity; drafts. ID prefix `ISS-`.

**Old sources covered:** routes `projects/(detail)/[projectId]/issues/**` and `browse/[workItem]`; `core/components/{issues, work-item-filters, rich-filters, dropdowns, gantt-chart, labels, readonly}`; `ce/components/{issues, rich-filters, relations, gantt-chart, de-dupe, epics, workflow}`; `core/store/issue/**`. The coverage checklist at the end maps every route file, component folder and API endpoint to the rows that cover it.

## How to read this file

Columns follow the Parity page row format:

| Field | Meaning |
| --- | --- |
| ID | `ISS-###`, stable, never reused |
| Capability | one user-observable capability |
| Who | role(s) that can use it; note what a role cannot do. `member+` = project ADMIN or MEMBER; guests are read-only unless stated |
| Edition | `oss` / `cloud` / `desktop` / `all`. `cloud` rows are features whose real implementation lives in the private `ee-overlay` (not in this checkout); in the OSS build they are absent or a no-op stub as noted |
| Old entry point | where the user triggers it (route + area), in prose |
| API | HTTP method + endpoint template, or `UI-only` / `client` / `n/a` |
| Acceptance | the observable outcome / rules a correct rebuild must reproduce |
| Parity test | left empty for now (filled by the oracle-scenarios issue) |
| Status | `not started` for every row (this is Stage 0) |

**API shorthand:** `BASE` = `/api/workspaces/{ws}/projects/{p}`. `{issues|epics}` is the `serviceType` path segment (`issues` for work items, `epics` for epics; epics differ on a few sub-paths noted inline). `WS` = `/api/workspaces/{ws}`.

## Method & scope notes (read before reviewing)

- Behavior was derived by **reading the old source** (`apps/web` `core/` + `ce/`) plus the shared `services`/`store` layers, not by translating code. The running-app pass and any cloud-only confirmation happen in the oracle-scenarios issue (NEWFRONT-28) and the human sign-off (NEWFRONT-8); rows found missing there return here as comments.
- **Editions.** This checkout contains only the OSS build: `core/` (shared base) + `ce/` (community-edition wiring). The **cloud** edition's overrides live in a private `ee-overlay` repo not present here. Where a `ce/` component is a no-op stub or an upgrade CTA, the row is marked `cloud` and its OSS behavior (absent / stub / CTA) is stated in Acceptance. Cloud-only Acceptance is described from the seams and call sites visible in OSS and should be re-verified against the running cloud app.
- **Desktop.** The desktop build renders the same web app; desktop-specific behavior in this area is confined to the agent execution target ("Runs on" / pod dropdown, e.g. `desktop_not_connected` / `byok_not_supported_on_desktop` reasons) and the managed/local runner options; those rows are marked `all` with desktop specifics in Acceptance.
- **Real-time.** There is **no** websocket / SSE / poll in the issue store layer. Lists and detail do not live-update from other users' changes; the only "refresh without reload" is self-initiated refetch after a mutation (parent stats, activity feed) plus in-memory optimistic updates. Captured as ISS-221. The one polling surface is the AI agent-status panel (ISS-164).
- **Old bugs.** None deliberately encoded. A few behaviors are quirks worth flagging to the oracle author, noted inline (e.g. move-issue route-change selection-clear is commented out; set-parent failure is silent).
