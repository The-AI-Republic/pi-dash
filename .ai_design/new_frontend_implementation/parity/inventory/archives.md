## Notes

- The old frontend's cycle/module restore calls use DELETE on
  `.../cycles|modules/{id}/archive/`, while the backend URLconf in this checkout
  exposes the unarchive DELETE under `archived-cycles|modules/{id}/unarchive/`. The
  rows record the frontend-called path; the oracle run (NEWFRONT-44) should confirm
  which path is live before writing scenarios.
- Bulk-archive (`bulk-archive-issues/`) is intentionally rowless here: its callers live
  on live Issues surfaces, so its row belongs to the Issues inventory, not this file.
- Live-path probe (NEWFRONT-225, ARCH-024): the frontend restore path DELETE
  `.../modules/{id}/archive/` returns 204 on the seeded stack and is the live app
  path; `.../archived-modules/{id}/unarchive/` 404s on `/api` (it exists only on
  the `/api/v1` token router). No bug; scenarios write against the frontend path.
- NEWFRONT-228 (ARCH-020, ARCH-022): a direct load or reload of the archived
  modules/cycles tabs in a fresh session hangs on the skeleton forever — the
  archived fetches never set `fetchedMap`, which every archived selector gates
  on. Intended: the tab renders from its own fetch on direct load. Oracle
  scenarios enter through the live screens plus client-side navigation until
  fixed; a `bug:` scenario pins the hang.
- NEWFRONT-229 (ARCH-021): the Filters menu button never shows its active
  indication — the wide variant carrying the dot is gated behind an `@4xl`
  container query with no `@container` ancestor on the list screens, so the
  narrow variant (no dot) always shows. Intended: the button indicates applied
  filters. A `bug:` scenario pins the absence.
- NEWFRONT-233 (ARCH-023, ARCH-024): a failed module archive/restore reports
  success — the store catches the write error and resolves, so the error
  confirmations are dead code; the success confirmation, close, and
  navigation/stay run while the server state stays unchanged. Intended: an
  error confirmation with no success path. A `bug:` scenario per row pins it.
- The workspace-level `projects/(detail)/archives/` routes (no project ID) render the
  projects list and are outside this area's scope.
