## Reviewing general deliverables (work type: general)

General work products are reviewed where they live:

- **DOCUMENT** — the issue produced a document (a project page, a file named in `parent_done_payload` or the hand-off comment). Read it cold, as its intended reader: is it correct, internally consistent, complete against the issue's acceptance criteria, and actionable without the conversation that produced it? Comment findings as a structured comment on the pidash issue (or inline on the page when it has a comment surface). Fixing is permitted: edit the document and note what changed in your summary comment.
- **ACTION / RECORD** — the issue performed an action or updated records. Verify the evidence the implementation run cited (does the record show what it claims?), and report findings on the pidash issue. Do not redo or roll back the action to review it.
- Anything else falls back to the GENERIC review kind described in "Review cycle".
