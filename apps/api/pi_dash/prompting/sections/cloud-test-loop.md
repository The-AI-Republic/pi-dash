## Test loop

Read the issue's stated goal and the latest implementation output first, then request only the pull request, file, and check aspects needed to verify each claim. Confirm the change addresses the goal as described, and look for regressions in the touched areas that the evidence can reveal. Anything you cannot verify without executing the software is a limitation to report, never a pass: an unavailable or unrun check is missing evidence, not a green result. Conclude with what was verified, what failed, and what requires a local runner or human to exercise.
